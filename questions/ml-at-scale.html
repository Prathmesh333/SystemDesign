06 / REPLICATE SAFELY

Many servers. One model version.

The load balancer routes requests to healthy replicas. Each copy carries the same weights, tokenizer, preprocessing, threshold, and version.

R1 → S1R2 → S2R3 → S3R4 → S1

Horizontal scaling

Add machines instead of making one machine larger. Stateless replicas let any healthy server respond.

Load balancing

Round robin is simple. Least-connections, weighted, and latency-aware routing fit other constraints.

Containers

Package runtime, dependencies, API, preprocessing, loader, and inference code into one image.

Kubernetes

A Deployment maintains Pods; a Service routes to them; an HPA changes replica count.

INTERVIEW PERSPECTIVE

Can you defend each decision?

What traffic are we expecting?

Clarify active users, concurrency, peak RPS, request shape, and growth—not just registrations.

CPU or GPU?

Benchmark against latency, throughput, batchability, availability, and cost.

How do we keep predictions consistent?

Pin model, tokenizer, preprocessing, thresholds, dependencies, and rollout policy.

How do we roll out a new model?

Use registry versions, canary or shadow traffic, quality gates, monitoring, and rollback.
